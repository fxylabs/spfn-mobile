Contracts/ · tools/contract-codegen계약 소비 파이프라인

SDK의 출발점은 손으로 쓴 타입이 아니라 서버가 발행한 계약 파일이다. upstream(spfn-primitives) CI가 export한 계약 JSON을 바이트 그대로 복사해 pin하고, 그 digest를 upstream.lock.json이 잠근다. codegen 도구가 이 계약에서 양 플랫폼의 타입·연산·에러 코드를 생성한다.

  • Contracts/spfn-mobile-contract.json — 계약 0.10.0 원본 (수정 금지, byte copy). 연산 16개, 타입 30개, enum 3개, 에러 코드 22개. auth.device.deny는 responseType을 선언하지 않으며, 그 경우 204 + 빈 본문이 계약이 정한 응답이다
  • tools/contract-codegen — Kotlin 기반 생성기 → SPFNGenerated* / SpfnGenerated*. 플랫폼당 다섯 파일: contract·types·operations·calls·errors
  • SPFNGeneratedCalls / SpfnGeneratedCalls — 연산 하나당 호출 서술자 하나. 연산 상수와 같은 이름이며(authDeviceApprove), 앱은 이 값을 execute에 넘긴다. 손으로 쓰는 서술자는 경로에 {provider} 치환이 필요한 auth.enroll.oauthNative 하나뿐이다
  • Contracts/fixtures/ — 요청 바이트·에러 봉투·enrollment 픽스처. 양 플랫폼 정합 테스트가 같은 파일을 읽는다

런타임에서 계약 호환성은 SPFNContractBinding이 판정한다. 지원 밖 서버는 나중의 디코딩 실패가 아니라 즉시 업그레이드 오류로 떠오른다.

0.x 라인에서는 minor가 파괴 축이라 상한이 다음 minor다. pre-release pin은 정확히 그 버전만 허용한다 — 범위 산술로는 통과해도 "아무도 pin하지 않은 버전의 pre-release"는 거절.

SPFNCore · spfn-core정본 직렬화

서명이 바이트 단위로 일치해야 하므로, JSON 직렬화 자체가 계약이다. SPFNCanonicalValue(568줄, 코어에서 가장 큰 파일)가 키 정렬·숫자 표기·문자 이스케이프를 고정하고, 두 플랫폼이 같은 입력에서 같은 바이트를 낸다는 것을 픽스처가 검증한다.

  • SPFNCanonicalJSON — 정본 인코딩/디코딩. 불가능한 값(비유한 수 등)은 생성 단계에서 실패
  • SPFNDecimalCoding — 십진 필드 전용 인코딩 (float 오차 배제)
  • SPFNDigest — SHA-256 lowercase hex, 본문 없는 요청의 고정 digest 상수 포함
  • SPFNCall / SpfnCall — 연산 + 요청/응답 코덱. 클라이언트가 아니라 코어에 있다: 생성 모듈이 코어에만 의존하면서 연산별 서술자를 들 수 있는 이유다. 응답을 선언하지 않는 연산은 noResponse 팩토리로만 만든다

SPFNClient · spfn-client키 수명주기

기기 키의 상태 머신은 unenrolled → enrolled → rotationPending 3가지 상태다. SPFNKeyLifecycle(541줄, 클라이언트에서 가장 큰 파일)이 enroll / rotate / resume / revoke를 소유하고, 키 자체는 플랫폼 보안 하드웨어가 쥔다.

  • iOS: SPFNSecureEnclaveKeyProvider — Secure Enclave 상주, 개인키 비추출
  • Android: SpfnKeystoreKeyProvider — Android Keystore 동형 구현
  • SPFNKeyStore — keyId·clientID 메타데이터 저장 (키 재료는 저장 안 함)

소셜 가입은 클로저 API다. 호출자는 provider SDK 호출만 담당하고, 논스 발급·본문 조립·실패 시 키 파기는 SDK가 소유한다.

SPFNClient · spfn-client세션과 실행 경로

SPFNSession은 핸드셰이크로 세션을 얻고, 요청마다 proof 헤더 묶음을 만들어 SPFNClient.execute에 공급한다. 만료·폐기(SESSION_REVOKED)를 읽으면 스스로 무효화한다.

API역할
handshake()세션 발급 왕복. 서버 계약 버전을 읽고 requireSupported로 판정
ensureSession()유효 세션 보장 — 없거나 만료면 핸드셰이크 재실행
proofHeaders(…)한 요청 몫의 서명·논스·시각 헤더 생성
invalidate(staleSessionID:)경합 안전 무효화 — 다른 태스크가 이미 새 세션을 얻었으면 보존

전송층은 iOS SPFNURLSessionTransport / Android SpfnOkHttpTransport. 중복 헤더 거절, 에러 봉투 6코드(PROOF_INVALID·PROOF_REPLAYED·SESSION_REVOKED 등) 분류는 SPFNClientError가 소유한다.

SPFNSocialApple · SPFNSocialGoogle · spfn-social-google소셜 로그인

어댑터는 provider SDK를 감싸 id_token 한 개만 돌려준다. 논스 변환 규칙이 핵심이다: Apple은 해시를, 나머지는 원문을 요구한다. 이 비대칭이 타입에 박제되어 있어 호출자가 틀릴 방법이 없다.

package init(fingerprint: String, provider: String)
{
    self.fingerprint = fingerprint
    self.provider = provider
    // 해시는 fingerprint의 "텍스트"를 대상으로 한다 — upstream hashNonce와 동일 규칙.
